# SchedAI ChatBot - Current Implementation Flow

This document details the step-by-step flow of how a user message is processed by the SchedAI ChatBot backend, specifically focusing on the `sendMessage` process.

## 1. Entry Point: `chat.sendMessage`
**File:** `app/controller/chat.controller.js`

1.  **Request Reception:** Receives `sessionId` and `message` from the frontend.
2.  **Session Retrieval:** Fetches the session from MongoDB.
3.  **Title Generation:** If it's the first message, uses GPT-3.5 to generate a 2-4 word chat title.
4.  **SSE Setup:** Sets up Server-Sent Events (SSE) headers (`text/event-stream`) to stream the response back to the client.
5.  **Abort Handling:** Sets up an `AbortController` to handle client disconnects and stop internal processing.
6.  **Persistence:** Saves the user's message to the session history.
7.  **Intent Processing Trigger:** Calls `getIntentFromOpenAI`.

---

## 2. Intent Detection: `getIntentFromOpenAI`
**File:** `app/utils/getIntentFromOpenAi.js`

This is the "Brain" of the operation. It decides what the user wants to do.

1.  **Vector Search:** Calls `searchAPIs(userMessage)` which uses embeddings to find the top most relevant APIs from `apiDetails.js`.
2.  **Context Building:** Prepares a summary of the conversation history (rolling context) to determine if this is a follow-up query.
### Intent Types & Internal Flows:

*   **`independent` (Fresh Query):**
    1.  Calls `handleParamsForApi` to normalize parameters and extract dates if needed.
    2.  If required fields are missing, generates a fallback prompt via OpenAI to ask the user.
    3.  If all fields are present, calls the API's `handler` (which usually calls the backend and then `processIntentAndFormatResponse`).

*   **`contextual_followup` (Referring to previous results):**
    1.  Triggered when user uses pronouns like "their", "them", or phrases like "the above drivers".
    2.  System calls `handleParamsForApi{isContextual: true}`.
    3.  Calls the API's `handler{isContextual: true}`.
    4.  **Internal Magic:** `processIntentAndFormatResponse` calls `applyContextualFilter`. It retrieves the IDs of entities displayed in the *previous* turn (stored in session context) and filters the *current* API's `actualData` to include ONLY those specific entities.

*   **`multi_intent` (Multiple APIs needed):**
    1.  Calls `handleMultiIntentApis` (Detailed below).
    2.  Aggregates data from multiple sources (e.g., Leave Requests + Weekly Hours).
    3.  **Final Step:** Calls OpenAI to intelligently merge all results into one cohesive HTML response, mapping data across APIs by common fields (like `DriverName`).

---

### Detailed Multi-Intent Implementation Logic:
**File:** `app/utils/handleMultiIntentApis.js`

1.  **API Iteration:** The system loops through each API identified by OpenAI.
2.  **Parameter Resolution:** For each API, it calls `handleParamsForApi` to resolve `ClientId`, `StationId`, and date ranges (`FromDate`, `ToDate`).
3.  **Data Fetching:** It calls the `multiHandler` of each API to fetch raw datasets. Unlike the standard `handler`, `multiHandler` returns raw data instead of a formatted string.
4.  **OpenAI Merging Prompt:** A specialized prompt is sent to GPT-4o-mini with the following rules:
    - **Data Integrity:** Explicitly distinguishes between `FORMAT_GUIDE_ONLY` (example schema) and `ACTUAL_REAL_DATA` (real records). AI is strictly forbidden from using example data.
    - **Entity Merging:** If APIs share a common entity (e.g., `driverName`), the AI creates a single unified <table>. If they are unrelated, it creates sequential sections.
    - **Key Normalization:** Matches entity names case-insensitively and handles minor spacing differences.
    - **HTML Enforcement:** Strictly valid HTML (no markdown), utilizing semantic tags (`<table>`, `<ul>`, `<p>`).
    - **Summary Insight:** Every multi-intent response must include a `<div class="summary">` with precise entity counts and meaningful insights.
5.  **Streaming:** The merged response is streamed back to the user chunk-by-chunk.
*   **`refinement_request` (Filtering/Sorting/Refining last response):**
    1.  Calls `refineResponseFromLastResponse`.
    2.  Uses OpenAI (`isSameIntent`) to check if the request is redundant.
    3.  If unique, OpenAI processes the `lastSuccessApiResponse` (cached data) and applies the user's requested filter or sort.
    4.  **Result:** Generates a new HTML response WITHOUT a new backend API call.

*   **`visualization_request` (Request for Chart/Graph):**
    1.  Calls `getGraphJsonFromLastResponse`.
    2.  OpenAI reads the HTML from the `lastResponseMessage`.
    3.  It converts that HTML table/list into a clean JSON array matching the API's schema.
    4.  Returns this JSON to the frontend for rendering charts (Bar, Pie, etc.).

*   **`handle_missing_field` (Providing required information):**
    1.  Triggered when the user answers a question like "Which station?".
    2.  System merges the new input into `session.missingField.lastParams`.
    3.  Resumes the original intended flow by calling `handleParamsForApi` and the API handler.

### Core Internal Utilities:

*   **Parameter Extraction (OpenAI):**
    - Done during intent detection. OpenAI extracts IDs (like `StationId: 5`) or marks them as `null` if the user provided a name instead of an ID (e.g., "for Jordan").

*   **Driver Name Matching:**
    - If `DriverId` is `null` but the API requires it:
    - Calls `extractDriverNamesFromMessage` (OpenAI) to extract names from the message.
    - Calls `findDriverIdByName` (Fuzzy matching) to find the ID in the session's `lmdpLists`.

*   **Parameter Handling (`handleParamsForApis.js`):**
    - **Auto-Fill:** Automatically adds `ClientId` and `StationId` from the active session.
    - **Date Logic:** If `WeekStarting` or `FromDate` are missing/required, calls `extractDateParamsFromOpenAI` or `handleFromDateToDate` to interpret "last week", "current week", etc.

## 3. Data Retrieval & Processing: API Handlers
**File:** `apiDetails.js`

1.  **Data Fetching:** Handlers typically use `axios` to fetch data from the actual backend API.
2.  **Data Mapping:** Maps the raw API response to a clean, structured object list.
3.  **Formatting Trigger:** Calls `processIntentAndFormatResponse`.

---

## 4. Final Formatting: `processIntentAndFormatResponse`
**File:** `app/utils/ProcessIntentAndFormatResponse.js`

1.  **Contextual Filtering:** If `isContextual` is true, it filters the data to only include entities referenced in the previous turn (e.g., the specific 10 drivers mentioned earlier).
4.  **Calculation Intent:** Calls `detectCalculationIntent` (via OpenAI).
    - **Detection:** AI analyzes the `userMessage` against the `apiDescription` and a sample of `actualData`.
    - **Logic:** It decides if math is needed (e.g., "Give me the average hours") and identifies the target `fieldPath` while ignoring metadata fields like IDs.
    - **Execution:** If math is required, it calls `performCalculations` from `app/utils/calculations.util.js`.
5.  **Response Generation:** Calls GPT-4o-mini to generate a final HTML response.

---

### AI-Powered Calculation Engine:
**Files:** `app/utils/calculations.util.js` & `app/utils/ProcessIntentAndFormatResponse.js`

1.  **Detection Phase (`detectCalculationIntent`):**
    - The system uses OpenAI to determine if the user is asking for a metric that the API doesn't already provide (e.g., Sum, Average, Multi-column deviation).
    - It returns a JSON object with `calculationType`, `fieldPath`, and `excludeZeros`.

2.  **Mathematical Processing (`calculations.util.js`):**
    - **Data Extraction:** `extractNumbers` recursively traverses the API data. It uses `isMetadataField` to strictly ignore IDs, timestamps, and status codes, ensuring math is only performed on meaningful numeric values.
    - **Nested Support:** `getNestedValue` allows the engine to calculate values deep within objects (e.g., `shifts.totalHours`).
    - **Operations:**
        - **Sum/Average:** Standard arithmetic on extracted numeric arrays.
        - **Deviation:** Calculates sample or population standard deviation.
        - **Percentage Deviation:** A complex operation that compares individual entities (like drivers) against the group average, identifying outliers and sorting them by impact.
        - **Min/Max:** Finds the range and extremes of the dataset.

3.  **Result Integration:**
    - The pre-calculated results are injected into the final OpenAI prompt under `### Pre-Calculated Results`.
    - The AI is instructed: **"Pre-calculated results are provided. You MUST use them."** This ensures mathematical accuracy by preventing GPT from performing the math itself, which can be prone to errors.

---

## Summary of the Chain
`Frontend` → `chat.sendMessage` → `getIntentFromOpenAI` → `API Handler` → `processIntentAndFormatResponse` → `OpenAI (Streaming)` → `Frontend`
